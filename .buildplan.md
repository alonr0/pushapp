# PushApp Build Plan

**Last updated:** 2026-09-30
**Purpose:** Durable product requirements, architecture reference, and implementation/verification checklist for the four-exercise reset.

## Product Goal

Build a mobile-friendly crew exercise tracker with fresh active-season scoring for push-ups, pull-ups, crunches, and squats. Preserve the previous push-up season and its snapshots as read-only legacy data; do not import legacy points into active standings.

## Product Requirements

### Scoring

- Daily repetition caps: push-ups 100, pull-ups 50, crunches 150, squats 150.
- Each category awards up to 25 base points, proportional to reps and rounded to one decimal place before categories are summed.
- Reaching an exercise cap adds 2 bonus points for that category. Reaching all four caps adds another 10 points. Daily maximum is 118 points.
- Reject a request that would exceed the remaining cap; never silently truncate it.
- A day qualifies for a streak at 60 base points, excluding completion bonuses.
- Award 5 separate lifetime points for every completed block of 7 consecutive qualifying days. These points do not increase daily scores or daily rankings.
- Use `Asia/Jerusalem` for the authoritative activity date in the database and client calculations, including daylight-saving transitions.

### Accounts and Groups

- Replace anonymous-only access with email/password, email link or one-time-code, and Google sign-in.
- A registered account joins one or more groups using a group code and display name. Joining creates a fresh active profile and never imports legacy totals.
- A group code is an identifier, not a password. Access control comes from the authenticated identity and database membership checks.
- Store provider credentials and production redirect URLs in Supabase Auth settings, not in browser code or this repository.

### App Experience

- Provide four capped exercise controls showing reps, category progress, points, and remaining reps.
- Show daily points, completion bonuses, streak progress, daily standings, all-time standings, and per-user history under the new scoring model.
- Remove active daily-goal editing and legacy goal indicators from the active experience.
- Persist light/dark theme and English/Hebrew language preferences.
- Translate core screens and share output. Set document language and direction correctly; Hebrew uses RTL and must work on mobile and desktop.
- Use the app's natural-color visual style and responsive layout consistently across authentication, workout, standings, and history screens.

### Legacy Data and Operations

- Preserve the initial schema migration and all existing legacy rows. Add schema changes only through forward migrations.
- Keep snapshot, rollover, backfill, podium, and history-maintenance scripts restricted to legacy tables and records.
- Do not run a linked/hosted migration until the hosted schema and migration history have been checked and the operator has approved applying it.

## Architecture

### Runtime and Client

- Vite serves the React application; `src/main.jsx` mounts `src/WorkoutApp.jsx`.
- `src/store.js` owns the Supabase client and legacy compatibility data access. `src/activeStore.js` is the active-season data-access layer.
- The browser uses only the Supabase project URL and publishable key. Service-role/secret keys remain server-side and must never use a `VITE_` or `NEXT_PUBLIC_` variable.
- Vite accepts both `VITE_` and `NEXT_PUBLIC_` env prefixes. `.env.local` currently targets the hosted project; `.env.development.local` targets local Supabase and is ignored by Git.

### Active Database Model

- Keep legacy tables `public.users` and `public.daily_leaderboards` intact and read-only to browser roles.
- Active tables: `public.workout_profiles`, `public.workout_daily_scores`, and `public.workout_streak_rewards`.
- Generated score fields in `workout_daily_scores` are the database source of truth for base points, bonuses, daily points, and streak qualification.
- `public.join_group` creates/updates group membership and the active profile for the signed-in registered user.
- `public.log_workout_reps` atomically verifies membership, applies a capped increment, calculates current scoring, and records completed streak-block rewards.
- RLS permits authenticated members to read data only for groups they joined. Active score writes go through the authorized RPC rather than direct table writes.
- `workout_profiles` and `workout_daily_scores` are included in Supabase Realtime publication for active group refreshes.

### Main Source Areas

- `src/WorkoutApp.jsx`: active authentication, group onboarding, exercise logging UI, standings, history, and preference controls.
- `src/activeStore.js`: active profile/group/score/reward reads, score RPC, and Realtime subscriptions.
- `src/workoutScoring.js`: client scoring constants, validation, streak calculations, and Israel date conversion.
- `src/workoutScoring.test.js`: focused scoring and timezone tests.
- `src/translations.js`, `src/index.css`, `index.html`: translations, themes/responsive styling, and document metadata.
- `src/leaderboardSnapshot.js`, `src/retroHistory.js`, and `scripts/`: legacy data helpers and maintenance. Keep this surface isolated from active workout tables.
- `api/send-push.js`: serverless push endpoint; authorize the bearer session and group membership before sending.
- `supabase/migrations/`: ordered schema changes. `202609240001_initial_schema.sql` is the preserved baseline.
- Local Vite does not serve the Vercel `/api/send-push` function; a push attempt returns 404 in plain Vite development. Exercise that endpoint through its local Vercel runtime or verify it separately.
